# Network Anomaly Detection Using Machine Learning

A cybersecurity dashboard that detects anomalous network traffic using an
unsupervised Isolation Forest model, served through a FastAPI backend and
visualized in a dark-themed React SOC dashboard.

## Objective

Flag anomalous network flow records (unusual duration, packet/byte volume,
failed connections, connection rate) without relying on labeled attack data,
and present them in an investigation-friendly interface.

## Architecture

```
CSV Dataset → Preprocessing → Isolation Forest → FastAPI → React Dashboard
```

- The backend loads a CSV on startup (or via upload), cleans it, encodes the
  `protocol` column, and fits an Isolation Forest on 8 numeric features.
- Predictions (`is_anomaly`, `model_anomaly_score`, `model_severity`) are
  computed once and cached in memory; API endpoints read from that cache.
- The frontend consumes the API and never computes anomaly logic client-side.

## Stack

- **Frontend:** React + Vite + Tailwind CSS + Recharts + Axios
- **Backend:** Python + FastAPI
- **ML:** pandas, NumPy, scikit-learn (Isolation Forest)
- **Storage:** In-memory (no database — not needed for this dataset size)

## Dataset

`network_anamoly_dataset.csv` — 1000 synthetic network flow records with
columns: `timestamp, source_ip, destination_ip, protocol, source_port,
destination_port, flow_duration_ms, packets, bytes, failed_connections,
connection_rate_per_min, label, anomaly_score, severity`.

`label`, `anomaly_score`, and `severity` are **dataset metadata only** — they
are never passed to the model. All predictions are generated by the deployed
Isolation Forest.

## ML Method

- **Model:** `sklearn.ensemble.IsolationForest` (`n_estimators=200`,
  `contamination="auto"`, `random_state=42`)
- **Features (ML input):** `protocol_encoded, source_port, destination_port,
  flow_duration_ms, packets, bytes, failed_connections,
  connection_rate_per_min`
- **Preprocessing:** drop rows with missing required fields, coerce numeric
  columns, label-encode `protocol`
- **Scoring:** `decision_function` output is inverted and min-max scaled to a
  0–1 `model_anomaly_score` (higher = more anomalous). Records with
  `predict() == -1` are flagged `is_anomaly = true`, then bucketed into
  Medium / High / Critical severity by score threshold.
- Because there is no validated ground-truth label used for training,
  precision/recall/F1/ROC-AUC are **not reported** anywhere in the dashboard.
  IMPORTANT: the dataset's own `label` column was used only as a one-time
  external sanity check during development (see below) — it was never fed to
  the model and is not exposed via the API.

## Setup

### Backend

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend runs at `http://localhost:5173`, backend at `http://localhost:8000`.

## API Usage

| Method | Endpoint                  | Description                                  |
|--------|----------------------------|-----------------------------------------------|
| GET    | `/api/health`              | Service health check                          |
| POST   | `/api/dataset/upload`      | Upload a new CSV and re-run the ML pipeline   |
| GET    | `/api/overview`            | Summary stats, timelines, protocol breakdown  |
| GET    | `/api/traffic`             | Paginated/filterable raw traffic log          |
| GET    | `/api/anomalies`           | Paginated/filterable anomaly list             |
| GET    | `/api/anomalies/{id}`      | Full detail for one record                    |
| GET    | `/api/model`                | Model metadata, features, settings            |

Filter query params: `protocol`, `severity`, `source_ip`, `destination_ip`,
`port`, `search`, `limit`, `offset`.

## Dashboard Pages

1. **Overview** — totals, traffic/anomaly timelines, protocol distribution, top IPs, recent anomalies. Includes an ⓘ "ML Info" button that opens a modal with model name/type, live record & anomaly counts, features used, excluded fields, and a short explanation of Isolation Forest (fed by `/api/model` and `/api/overview`).
2. **Network Analysis** — full traffic log with protocol/IP filters
3. **Anomalies** — filterable anomaly list (severity, protocol, search) with click-to-investigate
4. **Investigation** — search by anomaly ID or IP to view full record detail

A floating **NAVI** ("Network Assistant") button in the bottom-right corner opens a compact SOC-style chat panel available on every page. NAVI is a simple rule/intent-based assistant (no external AI service) that answers from the same `/api/overview`, `/api/model`, and `/api/anomalies/{id}` data already used by the dashboard — total events, anomaly counts/rate, protocol breakdown, top IPs, recent anomalies, individual anomaly lookups by ID, and explanations of the model and network fields. It always describes flagged records as "unusual traffic detected by the model," never as a confirmed attack, and says so plainly if requested data isn't available.

## Limitations

- Synthetic/demo dataset only — findings are illustrative, not real threat data.
- In-memory state: restarting the backend or uploading a new file replaces
  the current dataset entirely (no history across sessions).
- Isolation Forest is unsupervised; anomaly thresholds are heuristic, not
  tuned against a validated labeled dataset.
- No authentication — not intended for production/multi-user deployment as-is.

## Future Improvements

- Persist datasets and results in SQLite for session history
- Configurable contamination / threshold from the ML Info modal
- Real-time streaming ingestion instead of static CSV upload
- User accounts and role-based access for a real SOC deployment
